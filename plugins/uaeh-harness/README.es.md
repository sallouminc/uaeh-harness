# uaeh-harness — capa 2: el arnés de verificación

**Quien construye nunca verifica.** Este plugin añade a Claude Code la capa de control del método UAEH: revisores independientes que no pueden escribir, un sello de integridad alrededor de cada revisión, un registro de tareas, una guardia de cierre y una guarda de git en dos capas. Sus hooks **bloquean**. La capa 1 ([`uaeh-kit`](../uaeh-kit/README.es.md)) solo informa y es lo primero que se instala; la capa 3 (puertas) viaja en este mismo plugin: ya están la puerta de seguridad, la auditoría visual bajo pedido y el preflight (ver «Capa 3: puertas»).

English version: [`README.md`](README.md).

## Instalar

```
/plugin marketplace add sallouminc/uaeh-harness
/plugin install uaeh-harness@uaeh
/uaeh-harness:setup
```

`setup` corre el instalador **primero en seco** y pregunta antes de escribir. Qué hace, en orden:

1. **`config`** — crea `~/.claude/uaeh/uaeh.config.json` desde la plantilla (nunca pisa uno existente). Dos decisiones que vale la pena tomar ahí: `commits.credito` (`permitir` | `prohibir` la línea de crédito de Claude en los mensajes de commit, con una `commits.firma` obligatoria opcional) y `listaBlanca.agregar` (patrones de nombre de archivo que siempre cuentan como dinero, cuentas, base de datos o producción).
2. **`git-guard`** — copia la guarda de git a un espejo de ruta fija (`~/.claude/uaeh/estable/uaeh-harness/`), corre una **prueba de humo** en un repositorio temporal (un commit limpio pasa; un `.env` y un secreto falso se niegan) y solo entonces fija el `core.hooksPath` global al espejo. Un `core.hooksPath` existente (husky, otra guarda) nunca se pisa por su cuenta: se reporta y el usuario decide. Para sustituirlo, repite con `--reemplazar`: la prueba de humo corre igual antes, el valor anterior queda anotado y `git-guard --quitar --aplicar` lo restaura.
3. **`codex`** (opcional, apagado por defecto) — renderiza el bloque UAEH en `~/.codex/AGENTS.md` entre marcadores y los agentes `uae_*.toml` con los modelos de la configuración; imprime el fragmento de `config.toml` para pegar a mano. Usar Codex como auditor manda una copia limpia del repositorio a OpenAI: consentimiento explícito.

Requisitos: Node ≥ 20 en el `PATH`, git ≥ 2.31, Claude Code ≥ 2.1.295 (por `onFailure`). En Windows, Git for Windows (su `sh` corre los hooks de git). Reversa: `node "<plugin>/scripts/instalar.cjs" git-guard --quitar --aplicar` o `/plugin disable uaeh-harness`. Emergencia sin Node: `git config --global --unset core.hooksPath` en la terminal del usuario.

## Qué corre y qué bloquea

Todos los hooks van en forma exec (`command: "node"` + `args`, sin shell). `<P>` = la raíz del plugin.

| Evento | Matcher | Comando | ¿Bloquea? |
|---|---|---|---|
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/guardia-git.js` | **Sí.** Niega `git reset --hard`, `push --force`, `--no-verify` / `commit -n`, `clean -f` y cualquier intento de quitar la guarda de git (`core.hooksPath`, `GIT_CONFIG_*`, escribir `.git/config`). En `git commit` además busca en el texto secretos, archivos tipo `.env` y, si la política lo prohíbe, el crédito de Claude. `onFailure: block`: si Node falla, todo Bash/PowerShell queda bloqueado hasta reparar el hook o desactivar el plugin. |
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/uaeh-guardia-cierre.js commit` | No. Anota un `git commit` que toca archivos de lista blanca y le recuerda la regla al modelo. |
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/solo-lectura.js` | **Sí, solo para revisores.** Candado de solo lectura. Aplica a los agentes de `hooks/candados.json` (`uae-verifier`, `uae-security`, `browser-verifier`); en la sesión principal y en cualquier otro agente sale en silencio (compuerta por identidad: sin `agent_type` no hay candado). |
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/solo-navegador.js` | **Sí, solo para `browser-verifier`.** Lista blanca del verificador de navegador (clave `solo-navegador` de `hooks/candados.json`): solo Bash; `playwright-cli` con su sesión `uaeh-…` y subcomandos que no interactúan con la página; URLs `localhost`/`127.0.0.1`/`[::1]`; evidencia en `reports/visual-audit/`; `npx --no-install playwright test`, Lighthouse fijado, `git` de lectura y `curl -I` local. `open` exige una configuración de confianza: la plantilla del plugin (`templates/playwright-cli.config.json`) o `UAEH_HOME/playwright-cli.config.json`. Para ese agente falla cerrado; en cualquier otro sitio sale en silencio. |
| `SubagentStart` | los seis revisores | `node <P>/scripts/uaeh-integridad.cjs hook-inicio` | No. Toma la foto de integridad (repo + arnés). |
| `SubagentStop` | los seis revisores | `node <P>/scripts/uaeh-integridad.cjs hook-fin` | **Sí.** Si la foto está `ROTA` (algo cambió durante la revisión) o no se pudo medir, el revisor debe reportar `UNKNOWN`/`BLOCKED`, nunca PASS. |
| `SubagentStop` | `uae-verifier\|uae-security` | `node <P>/hooks/uaeh-guardia-cierre.js revisor` | No. Anota que corrió un revisor en esta sesión. |
| `Stop` | — | `node <P>/hooks/uaeh-guardia-cierre.js cierre` | **Sí, una vez por sesión.** No deja cerrar la respuesta si corrieron revisores y la tarea no está en el registro, o si hubo un commit de lista blanca sin ningún revisor. Falso positivo: `node <P>/hooks/uaeh-guardia-cierre.js directo "motivo"`. Apagar: crear `~/.claude/uaeh/guardia-cierre.apagada`. |
| `SessionStart` | — | `node <P>/hooks/linea-inicio.cjs` | No. Una línea si la guarda de git falta o está desactualizada, si `uaeh.config.json` tiene avisos o si el repo de la sesión tiene sello de preflight (vigente: no repetir; cambió o venció: incremental de lo cambiado). Si no, silencio. Habla al arrancar y tras `/clear`. |

Los matchers de agentes son expresiones regulares ancladas que admiten el prefijo del plugin (`uaeh-harness:uae-verifier`).

La guarda de git tiene una segunda capa **dentro de git**: `core.hooksPath` apunta a `git-hooks/` del espejo, cuyos despachadores llaman a `hooks/guardia-commit.cjs` desde el proceso real de git (índice, árbol y mensaje tal como git los ve, sin importar cómo se escribió el comando, incluidos `--no-verify`, `cherry-pick`, `rebase` y `am`). Niega secretos en las líneas añadidas (solo tipo y `ruta:línea`, nunca el valor), archivos sensibles, evidencias del navegador y, con política `prohibir`, el crédito o la identidad de Claude. Cada despachador encadena después el hook local del propio repositorio.

## Agentes, skill y scripts

- **Agentes** (`agents/`): `uae-verifier` (verificación independiente, YAML con las pruebas ejecutadas), `uae-security` (revisión de seguridad independiente; sin capa 3 sus hallazgos quedan `needs_validation`), `uae-builder`, `uae-architect`, `uae-triage`; para la puerta visual, `browser-verifier` (navegador bajo un candado de lista blanca) y `design-auditor` (solo lectura). Frontmatter neutral: el candado vive en `hooks.json`, no en el agente.
- **Skill** `/uaeh-harness:uae-loop <tarea>`: el protocolo para tareas de lista blanca (dinero · cuentas · base de datos · producción con datos reales). Construye la conversación principal, revisa una sola vez con `uae-verifier` (y `uae-security`) en paralelo bajo el sello, sin bucle de reintentos, seis estados finales, `UNKNOWN` nunca es PASS, línea de registro obligatoria.
- **Scripts** (`scripts/`): `uaeh-integridad.cjs foto <repo>` / `comparar <id> <repo>` (sello: `INTACTO` 0, `ROTA` 3, `DESCONOCIDO` 4), `uaeh-registro.cjs` (línea del registro), `uaeh-resumen.cjs [días]` (resumen del registro), `uaeh-huella.cjs` (superficie de riesgo y sello de preflight; la usa la capa 3), `instalar.cjs` (instalador), `doctor.cjs` (diagnóstico de la capa 2: git, la guarda global de git y su espejo, hooks duplicados en `settings.json`, copias personales de agentes o skills del plugin y tres autopruebas en carpetas temporales: humo de la guarda, candado de los revisores y sello; `--rapido` las salta), `lib/{comun,config,runner,diagnostico}.cjs`. `/uaeh-harness:doctor` corre los dos doctores (solo a mano).

## Capa 3: puertas

- **Seguridad** — `/uaeh-harness:uae-security`: pasada determinista de escáneres (gitleaks, semgrep, osv-scanner, cyber-neo vendorizado), un auditor Codex opcional de solo lectura de otra familia de modelos (manda una copia limpia del repositorio a OpenAI: requiere consentimiento) y pruebas de concepto en una caja de arena sin red sobre un motor de Linux con pines (`wsl/`: Windows 11 + WSL2, o Linux).
- **Visual, bajo pedido** — `/uaeh-harness:uae-visual`: solo cuando se pide una auditoría o antes de lanzar un sitio público; el trabajo visual del día a día se queda en la conversación con una captura para el responsable. Una ronda de chequeos deterministas con Playwright + axe (consola y red, desborde horizontal a 360 px, fuentes, WCAG 2.1 AA, captura contra una baseline aprobada), el agente `browser-verifier` y el agente `design-auditor` (contra el `DESIGN.md`, las Web Interface Guidelines de Vercel fijadas y WCAG); los hallazgos van a una lista para que el responsable decida. Preparar un proyecto: `node <P>/scripts/instalar.cjs visual --proyecto <repo>` (en seco; `--aplicar` escribe y nunca pisa un archivo del proyecto). Autoprueba de la puerta: `node <P>/skills/uae-visual/pruebas/probar-visual.cjs --instalar` (las dependencias van a `UAEH_HOME/cache/visual-fixture`). El catálogo de skills de ejecución que viaja es genérico, por rol; `instalar.cjs visual --registrar-skills` arma el borrador del tuyo (`UAEH_HOME/catalogo-visual.md`) desde tus skills instaladas.
- **Preflight, bajo pedido** — `/uaeh-harness:uae-preflight`: antes de un lanzamiento a producción o cuando se pide por su nombre; nunca se dispara solo. Corre en un contexto aparte (`context: fork`, Sonnet): consolida las auditorías previas, inventaría el repositorio y escribe 9 documentos en `docs/harness/` (perfil, mapa de datos, amenazas, línea base de seguridad, matriz legal, escala, aceptación, informe y lecciones), que sella con la huella de su superficie de riesgo y una vigencia según el riesgo (30, 60 o 90 días). No lanza subagentes: devuelve las delegaciones (seguridad, visual, base de datos, legal) a la conversación principal. Si después cambian `auth`, `esquema`, `env`, `rutas`, `manifiestos`, `despliegue` o `visual`, el siguiente preflight es incremental, solo de eso. En el repo de un cliente, el argumento `local` deja `docs/harness/` en el `.git/info/exclude` del clon. Para el proyecto, dos plantillas de script de verificación: `templates/verify.ps1` y `templates/verify.sh` (`0` pasa, `1` falla, `3` sin pruebas reales: nunca verde).
- **Doctor e instalador de puertas** — `node <P>/scripts/doctor-puertas.cjs [--puerta seguridad|visual|codex|preflight] [--rapido | --vivo]`: un veredicto por puerta, `LISTA` · `NO_INSTALADA` · `NO_LISTA` · `APAGADA` (Codex sin consentimiento: es opcional y no impide el veredicto global), y el comando que arregla cada falla. Seguridad lee lo instalado en el motor de Linux en una sola llamada de solo lectura (`wsl/estado.sh`: escáneres contra los pines, Docker como el usuario de la puerta, imágenes por digest, programas y validadores de `/opt/uaeh` iguales byte a byte al plugin y de root, `uaeh.conf` apuntando a la carpeta de corridas donde escribe la puerta). `--rapido` (~5 s) es lo que corre la puerta de seguridad antes de cada auditoría; `--vivo` suma la prueba de aislamiento de Codex (gasta cuota de Codex; el resultado se recuerda y vuelve a avisar si Codex cambia de versión) y la autoprueba visual con un navegador real. `node <P>/scripts/instalar.cjs puertas <puerta>` instala o repara solo lo que el doctor encontró faltante (en seco; `--aplicar`): en Windows corre los instaladores de Linux como root dentro de WSL después de copiar `/opt/uaeh` a `/opt/uaeh-respaldo/<fecha>` (`--actualizar` tras actualizar el plugin, `--reparar` para forzar los dos); en Linux imprime los comandos con `sudo`; lo que pide administrador, contraseña o cierra otras sesiones (instalar WSL, `wsl --terminate`, `codex login`) se imprime, nunca se ejecuta.
- **Consentimiento de Codex** — el auditor Codex solo corre con `codex.habilitado: true`; si no, `auditor-codex.cjs` sale con 3 (`NO_HABILITADO`) sin lanzar Codex. `instalar.cjs puertas codex --consiento --aplicar` lo enciende y deja la fecha en `codex.consentimiento`; `--retirar --aplicar` lo apaga.
- **Retención de corridas** — la puerta de seguridad guarda copias del código auditado en la carpeta de corridas. `node <P>/scripts/uaeh-runs.cjs listar|tamano|limpiar [--aplicar]`: en seco por defecto; compacta las corridas con más de `datos.retencion.completasDias` (30; borra solo las copias del código, conserva hallazgos, informes y evidencia), las borra pasados `borrarDias` (365), conserva siempre completas las `mantenerUltimas` (3) más recientes de cada repo, nunca toca `estado-hallazgos.json` y nunca sigue un enlace simbólico ni una unión.

## Configuración

Un solo archivo de usuario, `UAEH_HOME/uaeh.config.json` (por defecto `~/.claude/uaeh/uaeh.config.json`), nunca de proyecto. Precedencia: bandera > variable `UAEH_*` > archivo > defecto. Plantilla: `templates/uaeh.config.example.json`. Claves que usa la capa 2: `commits`, `listaBlanca`, `arnes.extra`, `zonaHoraria`, `wsl` (distro y usuario de la caja de arena, para la forma permitida del candado), `codex`. La capa 3 suma `datos.runs` (carpeta de corridas) y `datos.retencion` (retención de corridas), `codex.consentimiento` (fecha del consentimiento, la escribe el instalador), `visual` y `preflight.jurisdiccion` (jurisdicción de la matriz legal; vacía, el preflight la deduce del repo y la marca por confirmar). Una clave desconocida o un valor inválido producen un aviso y caen al valor por defecto; nada lanza jamás.

Variables de entorno que pisan el archivo: `UAEH_HOME`, `UAEH_TZ`, `UAEH_COMMIT_CREDITO`, `UAEH_COMMIT_FIRMA`, `UAEH_GIT_HOOKS` (dónde vive la guarda, para pruebas), `UAEH_ARNES` (reemplaza la lista del arnés medido, para pruebas), `UAEH_AHORA` (reloj fijo, para pruebas).

## Qué no garantiza

Los filtros de texto (`guardia-git.js`, `solo-lectura.js`; `solo-navegador.js` es más estrecho porque es una lista blanca con una sola gramática, la de Bash) son de mejor esfuerzo: un comando armado para evadirlos puede pasar. La garantía para un revisor es el **sello**: mide el resultado, no el comando. La capa de git no ve la plomería (`commit-tree`, `update-ref`) y un `core.hooksPath` local (husky) gana al global: la capa de texto detecta ese caso y se vuelve estricta. Un usuario con la misma cuenta puede reescribir el plugin o el espejo: es el residual declarado de la capa 2; la capa 3 añade la caja de arena sin red para el código auditado. Las listas completas de residuales están en la cabecera de cada script.

## Plataforma

Windows 11 + Git for Windows y Linux: probado (baterías unitarias en ambos en CI; el camino real en Windows). macOS: la capa 2 debería funcionar (Node + git), no probado. Puerta visual: probada en Windows 11 (navegador real, Lighthouse incluido); Linux y macOS sin probar. Preflight: la huella, el sello y las plantillas de verificación, probados en CI (Windows y Linux; `verify.ps1` solo en Windows PowerShell 5.1); la skill, en Windows 11.
