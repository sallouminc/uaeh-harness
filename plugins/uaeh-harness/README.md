# uaeh-harness — layer 2: the verification harness

**Whoever builds never verifies.** This plugin adds to Claude Code the control layer of the UAEH method: independent reviewers that cannot write, an integrity seal around every review, a task ledger, a closing guard and a two-layer git guard. Its hooks **block**. Layer 1 ([`uaeh-kit`](../uaeh-kit/README.md)) is informative and is the first thing to install; layer 3 (gates) ships in this same plugin: the security gate, the on-demand visual audit and the preflight are in (see «Layer 3: gates»).

Spanish version: [`README.es.md`](README.es.md).

## Install

```
/plugin marketplace add sallouminc/uaeh-harness
/plugin install uaeh-harness@uaeh
/uaeh-harness:setup
```

`setup` runs the installer **dry-run first** and asks before writing. What it does, in order:

1. **`config`** — creates `~/.claude/uaeh/uaeh.config.json` from the template (never overwrites one that exists). Two decisions worth making there: `commits.credito` (`permitir` | `prohibir` Claude's credit line in commit messages, with an optional mandatory `commits.firma`) and `listaBlanca.agregar` (file-name patterns that always count as money, accounts, database or production).
2. **`git-guard`** — copies the git guard to a fixed-path mirror (`~/.claude/uaeh/estable/uaeh-harness/`), runs a **smoke test** in a temporary repository (a clean commit passes; a `.env` and a fake secret are refused) and only then sets the global `core.hooksPath` to the mirror. An existing `core.hooksPath` (husky, another guard) is never overwritten on its own: it is reported and you decide. To replace it, repeat with `--reemplazar`: the smoke test still runs first, the previous value is recorded, and `git-guard --quitar --aplicar` restores it.
3. **`codex`** (optional, off by default) — renders the UAEH block into `~/.codex/AGENTS.md` between markers and the `uae_*.toml` agents with the models from your config; prints the `config.toml` snippet to paste by hand. Using Codex as an auditor sends a clean copy of the repository to OpenAI: explicit consent.

Requirements: Node ≥ 20 on `PATH`, git ≥ 2.31, Claude Code ≥ 2.1.295 (for `onFailure`). On Windows, Git for Windows (its `sh` runs the git hooks). Undo: `node "<plugin>/scripts/instalar.cjs" git-guard --quitar --aplicar` or `/plugin disable uaeh-harness`. Emergency without Node: `git config --global --unset core.hooksPath` in your own terminal.

## What runs, and what blocks

Every hook runs in exec form (`command: "node"` + `args`, no shell). `<P>` = the plugin root.

| Event | Matcher | Command | Blocks? |
|---|---|---|---|
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/guardia-git.js` | **Yes.** Denies `git reset --hard`, `push --force`, `--no-verify` / `commit -n`, `clean -f`, and any attempt to remove the git guard (`core.hooksPath`, `GIT_CONFIG_*`, writing `.git/config`). In `git commit` it also scans the text for secrets, `.env`-like files and (when your policy forbids it) Claude's credit. `onFailure: block`: if Node fails, every Bash/PowerShell call is blocked until the hook is repaired or the plugin disabled. |
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/uaeh-guardia-cierre.js commit` | No. Notes a `git commit` that touches whitelisted files and reminds the model of the rule. |
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/solo-lectura.js` | **Yes, for reviewers only.** Read-only lock. Applies to the agents listed in `hooks/candados.json` (`uae-verifier`, `uae-security`, `browser-verifier`); in the main session and in any other agent it exits silently (identity gate: no `agent_type` → no lock). |
| `PreToolUse` | `Bash\|PowerShell` | `node <P>/hooks/solo-navegador.js` | **Yes, for `browser-verifier` only.** Allowlist for the browser verifier (key `solo-navegador` in `hooks/candados.json`): Bash only; `playwright-cli` with its own `uaeh-…` session and subcommands that do not interact with the page; `localhost`/`127.0.0.1`/`[::1]` URLs; evidence under `reports/visual-audit/`; `npx --no-install playwright test`, pinned Lighthouse, read-only `git` and a local `curl -I`. `open` requires a trusted configuration: the plugin template (`templates/playwright-cli.config.json`) or `UAEH_HOME/playwright-cli.config.json`. For that agent it fails closed; anywhere else it exits silently. |
| `SubagentStart` | the six reviewers | `node <P>/scripts/uaeh-integridad.cjs hook-inicio` | No. Takes the integrity snapshot (repo + harness). |
| `SubagentStop` | the six reviewers | `node <P>/scripts/uaeh-integridad.cjs hook-fin` | **Yes.** If the snapshot is `ROTA` (something changed during the review) or could not be measured, the reviewer must report `UNKNOWN`/`BLOCKED`, never PASS. |
| `SubagentStop` | `uae-verifier\|uae-security` | `node <P>/hooks/uaeh-guardia-cierre.js revisor` | No. Notes that a reviewer ran in this session. |
| `Stop` | — | `node <P>/hooks/uaeh-guardia-cierre.js cierre` | **Yes, once per session.** Does not let the answer close if reviewers ran and the task is not in the ledger, or if a whitelisted commit happened without any reviewer. False positive: `node <P>/hooks/uaeh-guardia-cierre.js directo "reason"`. Off switch: create `~/.claude/uaeh/guardia-cierre.apagada`. |
| `SessionStart` | — | `node <P>/hooks/linea-inicio.cjs` | No. One line if the git guard is missing or outdated, if `uaeh.config.json` has warnings or if the session's repository has a preflight seal (current: do not repeat; changed or expired: incremental run of what changed). Silent otherwise. Speaks at startup and after `/clear`. |

Matchers for agents are anchored regexes that accept the plugin prefix (`uaeh-harness:uae-verifier`).

The git guard has a second layer **inside git**: `core.hooksPath` points to the mirror's `git-hooks/`, whose dispatchers call `hooks/guardia-commit.cjs` from the real git process (index, tree and message as git sees them, however the command was written, including `--no-verify`, `cherry-pick`, `rebase`, `am`). It refuses secrets in added lines (type and `path:line` only, never the value), sensitive files, browser evidence and, under a `prohibir` policy, Claude's credit or identity. Each dispatcher then chains the repository's own local hook.

## Agents, skill and scripts

- **Agents** (`agents/`): `uae-verifier` (independent verification, YAML with the executed tests), `uae-security` (independent security review; without layer 3 its findings stay `needs_validation`), `uae-builder`, `uae-architect`, `uae-triage`; for the visual gate, `browser-verifier` (browser under an allowlist lock) and `design-auditor` (read-only). Neutral frontmatter: the lock lives in `hooks.json`, not in the agent.
- **Skill** `/uaeh-harness:uae-loop <task>`: the protocol for whitelisted tasks (money · accounts · database · production with real data). Builds in the main conversation, reviews once with `uae-verifier` (and `uae-security`) in parallel under the seal, no retry loop, six final states, `UNKNOWN` is never PASS, mandatory ledger line.
- **Scripts** (`scripts/`): `uaeh-integridad.cjs foto <repo>` / `comparar <id> <repo>` (seal: `INTACTO` 0, `ROTA` 3, `DESCONOCIDO` 4), `uaeh-registro.cjs` (ledger line), `uaeh-resumen.cjs [days]` (ledger summary), `uaeh-huella.cjs` (risk surface and preflight seal, used by layer 3), `instalar.cjs` (installer), `doctor.cjs` (layer-2 diagnosis: git, the global git guard and its mirror, duplicate hooks in `settings.json`, personal copies of the plugin's agents or skills, and three self-tests in temporary folders: guard smoke test, reviewer lock, seal; `--rapido` skips them), `lib/{comun,config,runner,diagnostico}.cjs`. `/uaeh-harness:doctor` runs both doctors (manual only).

## Layer 3: gates

- **Security** — `/uaeh-harness:uae-security`: a deterministic scanner pass (gitleaks, semgrep, osv-scanner, vendored cyber-neo), an optional read-only Codex auditor from another model family (it sends a clean copy of the repository to OpenAI: opt-in) and proofs of concept in a network-less sandbox on a pinned Linux engine (`wsl/`: Windows 11 + WSL2, or Linux).
- **Visual, on demand** — `/uaeh-harness:uae-visual`: only when an audit is requested or before launching a public site; day-to-day visual work stays in the conversation with a screenshot for the owner. One round of deterministic Playwright + axe checks (console and network, horizontal overflow at 360 px, fonts, WCAG 2.1 AA, screenshot against an approved baseline), the `browser-verifier` agent and the `design-auditor` agent (against `DESIGN.md`, the pinned Vercel Web Interface Guidelines and WCAG); findings go to a list for the owner to decide. Prepare a project with `node <P>/scripts/instalar.cjs visual --proyecto <repo>` (dry run; `--aplicar` writes and never overwrites a project file) and self-test the gate with `node <P>/skills/uae-visual/pruebas/probar-visual.cjs --instalar` (dependencies go to `UAEH_HOME/cache/visual-fixture`). The shipped catalog of execution skills is generic, by role; `instalar.cjs visual --registrar-skills` drafts your own (`UAEH_HOME/catalogo-visual.md`) from your installed skills.
- **Preflight, on demand** — `/uaeh-harness:uae-preflight`: before a production launch or when requested by name; it never triggers itself. It runs in a separate context (`context: fork`, Sonnet): it consolidates earlier audits, inventories the repository and writes 9 documents in `docs/harness/` (profile, data map, threats, security baseline, legal matrix, scale, acceptance, report and lessons), sealed with the fingerprint of the risk surface and a validity that depends on the risk (30, 60 or 90 days). It launches no subagents: it hands the delegations (security, visual, database, legal) back to the main conversation. If `auth`, `esquema`, `env`, `rutas`, `manifiestos`, `despliegue` or `visual` change afterwards, the next preflight is incremental, covering only that. In a client's repository, the `local` argument keeps `docs/harness/` in the clone's `.git/info/exclude`. For the project, two verification-script templates: `templates/verify.ps1` and `templates/verify.sh` (`0` pass, `1` fail, `3` no real tests: never green).
- **Gate doctor and installer** — `node <P>/scripts/doctor-puertas.cjs [--puerta seguridad|visual|codex|preflight] [--rapido | --vivo]`: one verdict per gate, `LISTA` · `NO_INSTALADA` · `NO_LISTA` · `APAGADA` (Codex without consent: optional, it does not block the overall verdict), and the command that fixes each failure. Security reads what is installed in the Linux engine in a single read-only call (`wsl/estado.sh`: scanners against the pins, Docker as the gate user, images by digest, `/opt/uaeh` programs and validators byte-equal to the plugin and owned by root, `uaeh.conf` pointing at the runs folder the gate writes to). `--rapido` (~5 s) is what the security gate runs before each audit; `--vivo` adds the Codex sandbox probe (it counts against your Codex usage limits; the result is remembered and flagged again when Codex changes version) and the visual self-test with a real browser. `node <P>/scripts/instalar.cjs puertas <gate>` installs or repairs only what the doctor found missing (dry run; `--aplicar`): on Windows it runs the Linux installers as root inside WSL after copying `/opt/uaeh` to `/opt/uaeh-respaldo/<date>` (`--actualizar` after a plugin update, `--reparar` to force both); on Linux it prints the `sudo` commands; anything that needs an administrator, a password or closes other sessions (installing WSL, `wsl --terminate`, `codex login`) is printed, never run.
- **Codex consent** — the Codex auditor runs only with `codex.habilitado: true`; otherwise `auditor-codex.cjs` exits 3 (`NO_HABILITADO`) without starting Codex. `instalar.cjs puertas codex --consiento --aplicar` turns it on and records the date in `codex.consentimiento`; `--retirar --aplicar` turns it off.
- **Runs retention** — the security gate keeps copies of the audited code in the runs folder. `node <P>/scripts/uaeh-runs.cjs listar|tamano|limpiar [--aplicar]`: dry run by default; it compacts runs older than `datos.retencion.completasDias` (30; deletes only the code copies, keeps findings, reports and evidence), deletes them after `borrarDias` (365), always keeps the `mantenerUltimas` (3) most recent of each repository whole, never touches `estado-hallazgos.json` and never follows a symbolic link or junction.

## Configuration

One user file, `UAEH_HOME/uaeh.config.json` (default `~/.claude/uaeh/uaeh.config.json`), never a project file. Precedence: CLI flag > `UAEH_*` variable > file > default. Template: `templates/uaeh.config.example.json`. Keys used by layer 2: `commits`, `listaBlanca`, `arnes.extra`, `zonaHoraria`, `wsl` (sandbox distro and user, for the lock's allowed form), `codex`. Layer 3 adds `datos.runs` (runs folder) and `datos.retencion` (runs retention), `codex.consentimiento` (date of the consent, written by the installer), `visual` and `preflight.jurisdiccion` (jurisdiction of the legal matrix; when empty, the preflight infers it from the repository and marks it to be confirmed). Unknown keys and invalid values produce a warning and fall back to the default; nothing ever throws.

Environment overrides: `UAEH_HOME`, `UAEH_TZ`, `UAEH_COMMIT_CREDITO`, `UAEH_COMMIT_FIRMA`, `UAEH_GIT_HOOKS` (where the guard lives, for tests), `UAEH_ARNES` (replaces the measured harness list, for tests), `UAEH_AHORA` (fixed clock, for tests).

## What it does not guarantee

The text filters (`guardia-git.js`, `solo-lectura.js`; `solo-navegador.js` is narrower because it is an allowlist with a single grammar, Bash) are best-effort: a command crafted to evade them can pass. The guarantee for a reviewer is the **seal**: it measures the result, not the command. The git layer does not see plumbing (`commit-tree`, `update-ref`) and a local `core.hooksPath` (husky) wins over the global one — the text layer detects that case and turns strict. A user with the same account can rewrite the plugin or the mirror: that is the declared residual of layer 2; layer 3 adds the network-less sandbox for the audited code. Full residual lists are in the header of each script.

## Platform

Windows 11 + Git for Windows and Linux: tested (unit suites on both in CI; the real path on Windows). macOS: layer 2 should work (Node + git), not tested. Visual gate: tested on Windows 11 (real browser, Lighthouse included); Linux and macOS not tested. Preflight: the fingerprint, the seal and the verification templates are tested in CI (Windows and Linux; `verify.ps1` only on Windows PowerShell 5.1); the skill, on Windows 11.
